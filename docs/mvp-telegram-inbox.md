# MVP: сообщения из Telegram в Inbox

Минимальный набор требований. Один канал, никакой классификации, никаких действий
над заявкой. Задача среза — довести сообщение из Telegram до разбора в разделе
и убедиться, что цепочка работает целиком.

## Что режем и почему это не ломает большую картинку

| Из первой итерации | В MVP | Почему без противоречия |
|---|---|---|
| Три канала | Только Telegram, личный аккаунт | Канал, ради которого затевался раздел, и единственный технически недоступный другим инструментам. Модель заявки канало-независимая, почта и MTS.Link добавляются коллекторами |
| Классификация по пяти классам | Нет. Поле класса в модели есть и пустое | Классификация — надстройка над потоком. Пустое поле не мешает разбору вручную и заполняется, когда появится разметчик |
| TO REVIEW с комментарием модели | Нет | Состояние заявки хранится с самого начала, добавляется третьим значением без переделки |
| Вложения и ссылки | Только пометка «есть вложение» и выделенные ссылки, тела файлов не скачиваем | Локальное хранение файлов — отдельный слой, добавляется поверх без изменения модели |
| Цели квартала и спринта из Backlog.md | Нет | Нужны только классификатору, которого в MVP нет |

Инварианты, которые MVP обязан соблюсти, иначе срез противоречит картинке:
Inbox — состояние по умолчанию, ничего не отсеивается молча; ни одна заявка
не попадает в бэклог; хранилище одно и локальное; раздел ничего не отправляет
собеседнику.

## Требования

| ID | Требование |
|---|---|
| БТ-1 | Сообщение из отслеживаемого чата Telegram доходит до разбора без участия клиента Telegram: пропуск перестаёт зависеть от того, открыл ли Product Owner приложение |
| ПТ-1 | Список Inbox: все собранные заявки, новые сверху, без предварительного отсева |
| ПТ-2 | Заявка помечается разобранной вручную и уходит из Inbox, оставаясь в истории |
| ПТ-3 | Заявка, собранная после простоя машины, видна как пришедшая с задержкой |
| ИТ-1 | Раздел «Управление коммуникацией» в UI харнесса: список Inbox и счётчик неразобранных |
| ИТ-2 | Карточка в сайдбаре: автор, время, текст, тред вокруг сообщения (что было до и после), пометка наличия вложений, выделенные ссылки |
| ФТ-1 | Коллектор читает личный аккаунт Telegram клиентом на MTProto и забирает сообщения из чатов, перечисленных в реестре отслеживаемых |
| ФТ-2 | Каждое сообщение сохраняется как заявка канало-независимой формы: канал, автор, время, текст, идентификатор треда, состояние, пустое поле класса |
| ФТ-3 | Вокруг сообщения сохраняется тред: соседние сообщения диалога до и после |
| ФТ-4 | Состояния заявки: `inbox` и `разобрано`. Значение по умолчанию — `inbox`, других путей появления заявки нет |
| ФТ-5 | Заявка, собранная позже своего появления в канале сверх бюджета задержки, помечается признаком задержки |
| ФТ-6 | Раздел не пишет в бэклог и не отправляет ничего в канал |
| НФТ-1 | Задержка от появления сообщения в чате до появления заявки в Inbox — не более 5 минут при работающей машине и сети. **Измерено 2026-09-09 на живом аккаунте: медиана 0.63 с, максимум 1.07 с, минимум 0.09 с на выборке из 7 личных сообщений; потерь нет.** Бюджет в пять минут описывает не транспорт, а возврат после сна машины |
| НФТ-2 | Хранилище локальное, файловое, без отдельного сервера СУБД. Один потребитель, один инстанс |
| НФТ-3 | Перезапуск машины и разрыв сети не приводят к потере или дублированию заявок: коллектор продолжает с последнего обработанного сообщения |

## How to demo

1. Добавляю чат Telegram в реестр отслеживаемых.
2. Пишу в этот чат тестовое сообщение.
3. Открываю раздел «Управление коммуникацией» и вижу заявку в Inbox не позже пяти минут.
4. Нажимаю карточку, вижу автора, время, текст и тред вокруг сообщения.
5. Помечаю заявку разобранной, она уходит из Inbox и остаётся в истории.
6. Закрываю ноутбук, пишу в чат, открываю ноутбук: заявка приходит с пометкой задержки.
7. Проверяю, что в бэклоге не появилось ничего.

## Границы MVP

В зоне: один канал Telegram, реестр отслеживаемых чатов, локальное хранилище заявок,
список Inbox, карточка с тредом, ручная пометка разбора, признак задержки.

Не входит: почта, MTS.Link, классификация и любая LLM, TO REVIEW, ответ из карточки,
заведение задач, планирование созвонов, скачивание вложений, цели из Backlog.md,
разметка истории задним числом.
