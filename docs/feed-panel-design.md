# Лента контура в dsh: правый столбец, фрейм, метки

Как раздел «Управление коммуникацией» показывает ленту контура внутри DeepSeek
Harness и фильтрует её настраиваемыми метками. Записано 2026-09-11; каждое
утверждение о поведении сервера и клиента проверено запросом или в браузере,
а не прочитано.

Прототип: [`ui/feed-frame-prototype.html`](ui/feed-frame-prototype.html).
Открывать с `127.0.0.1` (см. «Почему именно 127.0.0.1»).

---

## Сценарий

1. Открыть dsh.
2. Нажать «Управление коммуникацией» в подвале левой панели.
3. Справа открывается столбец с лентой.
4. Клик по посту открывает его с веткой, опросом и полем ответа.
5. Пилюли над лентой переключают срез: Разработка, Продукт, Маркетинг, …
6. Метки настраиваются в **Настройки → Плагины → Конфигурация плагинов →
   «Управление коммуникацией»**: название и правила. Шестерёнка у пилюль ведёт
   туда же.

---

## Решение: лента не рисуется, а встраивается

В столбце стоит `iframe` с работающим клиентом ленты (Phanpy,
`http://127.0.0.1:8083`). Своего UI ленты в плагине нет — посты, ветки,
опросы, ответы, вложения и панель Shortcuts уже есть у клиента, и в ширине
столбца он сам уходит в мобильную раскладку: Shortcuts становятся нижними
вкладками, клик по посту открывает его поверх ленты. Шаг 4 сценария — это
поведение клиента, а не наш код.

Что плагин пишет сам — ровно три вещи:

| Часть | Где в dsh | Что своего |
|---|---|---|
| Кнопка раздела | `sidebar.footer.action` | уже есть |
| Столбец: шапка, пилюли, фрейм | `shell.overlay` | пилюли из настроек, `src` фрейма |
| Карточка настроек меток | `settings.plugin.item` | список меток и правил, «Применить к ленте» |

Слот `details` (правая колонка dsh) не подходит: `single`, занят деталями
инструмента и живёт только при открытой сессии. `shell.overlay` — аддитивный.

### Проверено

| Что | Ответ |
|---|---|
| Phanpy во фрейме | заголовков-запретов нет — встраивается |
| GoToSocial во фрейме | `x-frame-options: DENY` на всём, включая `/auth/sign_in` |
| Тема | Phanpy слушает системную тему, не переключатель dsh |

Следствие второго пункта: **войти внутри фрейма нельзя.** Вход делается один
раз в обычной вкладке `127.0.0.1:8083`; фрейм подхватывает токен из хранилища
клиента.

### Почему именно 127.0.0.1

Браузер делит хранилище фрейма по *сайту верхнего окна*. `127.0.0.1:3080` (dsh)
и `127.0.0.1:8083` (Phanpy) — один сайт, порт в понятие сайта не входит.
`localhost` — уже другой сайт, `file://` — тем более: там фрейм окажется
не залогинен при залогиненной вкладке, и понять это по виду нельзя. dsh по
умолчанию поднимается на `127.0.0.1` — совпадение нам на руку.

### Швы

- **Оболочка слепа.** Клик по посту внутри фрейма dsh не видит: другой origin.
  Значок «ждут тебя» считается узловой половиной плагина запросом к API ленты с
  токеном человека — единственный кусок кода, который смотрит на содержимое.
- **Столбец накрывает** правый край беседы, а не сдвигает её. Сдвигать умеет
  только `details`, он занят. Если накрытие мешает — нужен слот `shell.aside`
  в самом dsh.

## Метки: хэштег, правила, правка постов

### Почему хэштег

Клиенту нужно уметь показать *подмножество ленты* по одному адресу. Что у
сервера есть для этого:

| Механизм | Годится? |
|---|---|
| лента по тегу `timelines/tag/{tag}` | да |
| список | нет — это набор учёток, не постов |
| поиск по тексту чужих постов | нет — сервер не даёт |
| объединение тегов `?any[]=` | **нет — сервер молча игнорирует.** Проверено: два поста с разными тегами, `any[]` возвращает один |
| неиспользованный тег | `404 tag was not found` |

Значит **одна метка = один хэштег = одна лента**, и фильтр — переключатель, не
мультивыбор. Пост может нести несколько меток и попадать в несколько срезов.

### Почему правка постов

Чужому посту хэштег не поставить. Но чужих постов в ленте нет: каждый написан
нашей учёткой — источником Telegram или агентом, — и токены у нас. Поэтому
метка ставится:

- **при публикации** — `Feed._labeled` в мосте, `with_labels` в переносе из
  Telegram; единственная точка выхода текста в ленту;
- **перемаркировкой** — `scripts/relabel.py` правит уже опубликованные посты
  (`PUT /api/v1/statuses/{id}`), сервер перечитывает теги. По умолчанию только
  показывает, что изменилось бы; `--apply` правит; повторный прогон — ноль правок.

**Посты с опросом и вложениями перемаркировке не подлежат.** Проверено: `PUT`
без повтора параметров опроса убивает опрос при ответе `200`; с повтором —
опрос пересоздаётся с новым `id`, и мост, помнящий старый, перестаёт видеть
голоса. Такие посты получают метки только при публикации; перемаркировка
перечисляет их отдельной строкой, чтобы их не считали размеченными.

### Без префикса — намеренно

Системные теги `#контур_…` ведут к действию: чужой пост под ними — ложное
голосование, поэтому им нужен префикс. Метка — только фильтр. Если канал
Telegram сам пометил пост `#маркетинг`, попадание его в срез «Маркетинг» — не
ошибка, а разметка, сделанная за нас.

### Файл правил — один на всех

```json
{ "labels": [
  { "id": "разработка", "title": "Разработка",
    "rules": [ { "account": "openhands" }, { "tag": "контур_задача" } ] },
  { "id": "клиенты", "title": "Клиенты",
    "rules": [ { "account": "tg_aleks" }, { "contains": "клиент" } ] }
] }
```

Метка ставится, если подходит **хотя бы одно** правило. Виды: `account`
(учётка-автор), `tag` (на посте уже стоит тег), `contains` (подстрока без
регистра), `regex`, `prompt` (описание для модели). `id` обязан быть годным
хэштегом; сломанный файл роняет писателя **до** первой публикации, а не
оставляет посты без меток молча.

### Правило «промт»

Когда признаков в тексте нет, а по смыслу пост относится к метке:

```json
{ "prompt": "Переписка с партнёром MTS Live: созвоны, договорённости, сроки
             интеграции — даже если слово «Live» в тексте не встречается" }
```

Модель — самое дорогое и медленное, что здесь есть, поэтому:

- промт проверяется **последним** и только для меток, не подошедших
  механически;
- **один вопрос на пост** со всеми промт-метками разом, ответ — JSON со
  списком id; всё, что не разбирается, — ошибка вслух, не «не подошло»;
- ответ **запоминается** по хэшу (учётка, текст, промты) в
  `labels-judgments.json` рядом с файлом меток. Прогон по ленте — 103 вопроса,
  повторный — 0. Новый промт — новый хэш — спрашивает заново сам;
- при публикации отказ модели **не блокирует пост**: уходит без промт-меток,
  с криком в stderr; перемаркировка доспросит;
- промт-метки **без модели отказываются стартовать**: `LABELS_LLM_BASE_URL`,
  `LABELS_LLM_API_KEY`, `LABELS_LLM_MODEL` обязательны, иначе пропущенный
  промт неотличим от «не подошло».

Поставщик — OpenAI-совместимый чат из окружения; контур ходит в GLM через
z.ai, здесь тот же адрес (`bridge/judge.py`, stdlib, без SDK).

Живая проверка: «подтверждаем созвон в четверг по интеграции витрины…» → `live`;
«Запуск сервиса поиска стартапов» → пусто. На ленте модель отнесла к Live
«Мы начали трансляцию» — прочитала как прямой эфир. Это точность промта,
и правится она в карточке настроек, а не в коде.

Лежит рядом с базой заявок — `communication/labels.json` под `workspaceRoot`
плагина. Его читают мост и перенос (`LABELS_FILE`), правит страница настроек.
Две копии одной настройки разъезжаются, поэтому путь один.

Движок — `bridge/src/bridge/labels.py` в `poh-feed-poc`, один на всех
писателей. У плагина своей реализации правил нет: он редактирует файл и
запускает перемаркировку.

## Что делать в плагине

1. **Столбец.** Пилюли из `labels.json`; клик — `src` фрейма на
   `#/feed.localtest.me/t/{id}`, «Все» — `#/`. Пустые метки (404 по тегу)
   гасить: узловая половина считает посты по тегу с токеном человека.
2. **Настройки.** Карточка `settings.plugin.item` с ключом пространства
   настроек плагина — в dsh это стопка карточек во вкладке «Конфигурация
   плагинов»: заголовок «имя + чем управляет» раскрывается на месте,
   Сохранить/Отменить в карточке, «Не сохранено» в заголовке. Внутри — метки
   и правила (промт — многострочное поле), «Применить к ленте» запускает
   перемаркировку отдельным процессом (как коллектор) и показывает вывод.
3. **Канал.** Подкоманды `labels.list`, `labels.save`, `labels.apply`,
   `feed.counts`. Существующие `list/show/done/label` не трогаются.

Что остаётся ручным: вход в Phanpy (один раз), тема Phanpy.
