# Работа с этим репозиторием

Раздел «Управление коммуникацией» для DeepSeek Harness: Inbox входящих, разбор, тред.

## Прежде всего

**[docs/PRINCIPLES.md](docs/PRINCIPLES.md) — два нерушимых принципа.** Доступ к данным
только через порт; внешние идентификаторы канала хранятся с самого начала. Изменение,
которое их нарушает, возвращается, а не обсуждается.

Границы первой итерации — [docs/mvp-telegram-inbox.md](docs/mvp-telegram-inbox.md).
Долгосрочная развилка по хранилищу — [docs/chatwoot-as-backend.md](docs/chatwoot-as-backend.md).

## Тесты

Два круга. Обычный `npm test` в сеть не ходит вовсе: клиент канала приходит портом,
поэтому логика сбора, хранилище, канал и состояние проверяются подделкой порта.

Живой круг проверяет то, что подделка проверить не может — что система действительно
читает данные из Telegram: вход по сохранённой сессии, история настоящими сообщениями,
порог непрочитанного, путь «Telegram → заявка в базе», отсутствие дублей при повторе.
Он ничего не отправляет: только чтение, чтобы прогон не оставлял следов в переписке.

```sh
npm test                                  # без сети и без аккаунта
RUN_LIVE_TESTS=1 npm run test:live        # с сессией, только чтение
RUN_LIVE_TESTS=1 LIVE_TEST_CHAT=@канал npm run test:live
```

Без `RUN_LIVE_TESTS=1` живые тесты помечаются пропущенными с причиной, а не падают:
обычный прогон не должен зависеть от аккаунта.

## Обязательная проверка после любой доработки

Правка исходников, манифеста профиля или `cordis.patch.yml` не считается завершённой,
пока харнесс не поднялся: **несобранный плагин роняет весь харнесс, а не свой раздел** —
cordis считает такую запись фатальной, и launchd крутит рестарт по кругу.

```sh
npm test && npm run build
launchctl kickstart -k gui/$UID/ru.poh.dsh-harness
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3082/   # ожидаем 200
```

Порт поднимается не мгновенно — опрашивать до 30-40 секунд. Не 200 или пусто — смотреть
`tail -40 /tmp/dsh-harness-ui.log`, чинить, повторять. Не отчитываться о готовности,
пока не получен 200: агент в `launchctl list` живой и при сломанном харнессе.

## Что раздел не делает

Не пишет в бэклог ничего. Не отправляет ничего в канал: отправку наружу всегда
подтверждает человек. Не заводит второго хранилища одних и тех же сущностей.

## Секреты

Ключ приложения Telegram и путь к сессии живут в `.env` в корне пакета: `TG_API_ID`,
`TG_API_HASH`, `TG_SESSION`. Файл в репозиторий не попадает, в него смотрят и командная
строка, и раздел внутри харнесса. Заготовка — `.env.example`, её и правим при добавлении
новой настройки.

Разбор файла свой (`src/env-file.ts`), а не `process.loadEnvFile`: тот кладёт значения
в `process.env` всего процесса, то есть внутри харнесса — в окружение, видимое любому
его инструменту. Ключ остаётся значением, которое читает только этот раздел.

В `cordis.patch.yml` и любых файлах репозитория секретам не место.
