# Спайк: коллектор личного Telegram в локальный Inbox

Прототип к [#2](https://github.com/po-helper-org/dsh-communication-plugin/issues/2)
и [#8](https://github.com/po-helper-org/dsh-communication-plugin/issues/8). Не плагин
и не часть контура: отдельный скрипт, который доказывает, что цепочка от личного
сообщения до разбора собирается.

Разбор кандидатов и итог — [docs/spike-mtproto.md](../../docs/spike-mtproto.md).

## Запуск

```sh
npm install
export TG_API_ID=...      # my.telegram.org, раздел API development tools
export TG_API_HASH=...
```

Список отслеживаемых чатов — `watched.json`: username, ссылка или идентификатор.

```sh
node collect.mjs      # вход в аккаунт, догон пропущенного, затем поток
node inbox.mjs        # список Inbox
node inbox.mjs show <ключ>    # карточка: тред до и после, вложения, ссылки
node inbox.mjs done <ключ>    # пометить разобранной
node selftest.mjs     # проверка логики хранилища без сети и без аккаунта
```

Вход в аккаунт выполняет владелец: Telegram присылает код в приложение, скрипт
спрашивает его в терминале. Сессия ложится в файл `tg.session`, заявки — в `inbox.db`,
оба вне репозитория.

## Устройство

`store.mjs` — модель заявки и хранилище на `node:sqlite`. Заявка канало-независимая:
канал это колонка, поле класса пустое до появления разметчика. Состояний два:
`inbox` и `разобрано`, других путей появления заявки нет.

`collect.mjs` — клиент на [mtcute](https://github.com/mtcute/mtcute). При старте догоняет
пропущенное от последнего обработанного сообщения по каждому чату, затем слушает поток.
Повторный проход по тем же сообщениям дублей не создаёт и разбор не сбрасывает.
Заявка, собранная позже пяти минут с момента отправки, помечается признаком задержки.

`inbox.mjs` — разбор из терминала. Тред собирается из локальной базы, в сеть за ним
ходить не нужно.

Раздел ничего не отправляет в канал и ничего не пишет в бэклог.
