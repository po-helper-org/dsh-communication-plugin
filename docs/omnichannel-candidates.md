# Кандидаты ядра для омниканального доступа ИИ-агентов

Закрывающая сводка исследования 2026-09-09. Задача сформулирована отдельно от MVP-скоупа
плагина: не «собрать наши четыре канала», а «какое существующее ядро взять под
расширяемый омниканальный источник для ИИ-агентов», сервер допустим.

## Решения

| Кандидат | Ссылка | Почему |
|---|---|---|
| Unipile | [unipile.com](https://www.unipile.com/) | Просто работает, за деньги. Единственный, кто закрывает личные аккаунты во всех наших каналах разом. Не OSS, чужой сервер между сообщением и нами — конфликт с решением «сам размещаю, сам отвечаю за риски» |
| Beeper | [developers.beeper.com](https://developers.beeper.com/) | SaaS-версия Synapse+mautrix: тот же движок, упакованный и проданный. Подтверждено отдельной проверкой — не гипотеза |
| [automagik-dev/omni](https://github.com/automagik-dev/omni) | — | Спроектирован под агентское потребление: event bus, identity graph, response gate (= «отправляет всегда человек»), Channel SDK как плагин. Наших каналов там ноль — три адаптера писать всё равно самим |
| [element-hq/synapse](https://github.com/element-hq/synapse) + [mautrix/telegram](https://github.com/mautrix/telegram) | — | Архитектурно оправдан, если планируется highload и широкий охват потребительских сетей: реестр `mautrix` держит готовые мосты для WhatsApp, Slack, Instagram, Discord, Signal, LinkedIn и другие (проверено обходом организации на GitHub). **Требует выделенный сервер** — прямое противоречие ограничению «клиентское приложение без выделенных серверов», если это ограничение остаётся в силе |

## Дополнение (не кандидаты, для полноты)

| Проект | Ссылка | Почему не кандидат |
|---|---|---|
| Novu | [novu.co](https://novu.co/) | OSS, мощный, но движок **исходящих** уведомлений (email/SMS/push/чат). Наша задача — сбор входящего, направление обратное |
| Chatwoot | [chatwoot.com](https://chatwoot.com/) | OSS, зрелый helpdesk-движок, действительно мощный. Дисквалифицирован по одному конкретному основанию, не по силе продукта: Telegram только через Bot API, личные диалоги не отдаёт; VK канала нет вовсе. Разбор и закрытие — [docs/chatwoot-as-backend.md](chatwoot-as-backend.md), [issue #9](https://github.com/po-helper-org/dsh-communication-plugin/issues/9) |

## Что покрыто по нашим каналам фактом, не мнением

| Канал | Unipile | Beeper/Synapse+mautrix | Omni | Chatwoot |
|---|---|---|---|---|
| Telegram, личный | ✅ | ✅ puppeting | ❌ Bot API | ❌ Bot API |
| VK, личный | ✅ | ❌ моста нет (проверено) | ❌ | ❌ |
| Email | ✅ | ❌ моста нет | ❌ | ✅ |
| MTS.Link | ❌ | ❌ | ❌ | ❌ |

Ни один кандидат не закрывает MTS.Link — собственный коннектор нужен при любом выборе ядра.

## Что уже сделано

Плагин `dsh-communication-plugin` — свой тонкий коллектор поверх `ChannelPort`
(mtcute для Telegram сегодня), а не адаптация одного из этих ядер. Решение не пересмотрено
этим исследованием: ни один кандидат не даёт готового покрытия наших каналов дешевле,
чем цена его подключения (сервер, чужая инфраструктура или написание тех же адаптеров
с нуля против чужого SDK). Три идеи забраны на будущее без смены архитектуры:
identity graph и response-gate из Omni, широта каталога мостов mautrix как ориентир,
если понадобится WhatsApp/Slack/Instagram.
