# Раздел «Управление коммуникацией» в DeepSeek Harness

Как поднять `dsh-communication-plugin` в харнессе — по шагам, которые отработали на
живой установке 2026-09-12. Каждая «грабля» ниже — не предположение: на ней что-то
сломалось при первом прогоне.

Что получается: кнопка в подвале левой панели, правый столбец с лентой контура
(фреймом), пилюли меток над ним, карточка настроек в «Настройки → Плагины».

## Что нужно заранее

| Что | Зачем | Проверка |
|---|---|---|
| Node.js ≥ 22, pnpm | сборка плагина и харнесса | `node -v`, `pnpm -v` |
| Лента контура (`poh-feed-poc`) | инстанс, клиент и `seed.html` | `./tests/test_login_e2e.sh` там |
| Токен человека в ленте | фрейм входит им сам | `./scripts/get_tokens.sh aleks` в `poh-feed-poc` |
| Харнесс из исходников, `0.1.2-alpha.5` | API плагинов alpha, версия закреплена | `git log -1` в каталоге харнесса |

## 1. Плагин

```sh
cd dsh-communication-plugin
npm install && npm run build      # tsc в lib/ + браузерный бандл lib/client.js
```

> **Грабля.** Плагин без собранного `lib/index.js` роняет харнесс целиком — cordis
> считает такую запись фатальной. `lib/` не в репозитории: после клона сборка обязательна.

## 2. Профиль харнесса

Профиль `web` в `$DSH_HOME/profiles/web/`. В `package.json` — зависимость `link:` на
каталог плагина и его имя в `dsh.profile.bundles`. В `cordis.patch.yml` — слой
конфигурации по идентификатору `communication-inbox`:

```yaml
- id: communication-inbox
  config:
    workspaceRoot: '/абсолютный/путь/к/воркспейсу'
    dbPath: 'communication/inbox.db'
    labelsPath: 'communication/labels.json'
    relabelCwd: '/абсолютный/путь/к/poh-feed-poc'
    relabelCommand: 'set -a; . ./.env; set +a; python3 scripts/relabel.py'
```

> **Грабля.** Слой профиля **заменяет** конфигурацию пакета целиком, а не дополняет. Задав
> здесь `workspaceRoot`, вы теряете умолчания из `cordis.patch.yml` пакета — поэтому
> `dbPath` и `labelsPath` повторены явно.

`relabelCommand` — то, что узел выполнит оболочкой по кнопкам «Что изменится» /
«Применить к ленте»; к команде дописывается ` --apply`. Пусто — кнопки погашены с
подсказкой. Команда живёт в конфигурации, а не в настройках из браузера, намеренно.

## 3. Запуск

```sh
cd harness
DSH_HOME="$PWD/.dsh-data" pnpm dsh web --no-open --port 3082
```

> **Грабля.** Харнесс не подхватывает плагин на живую: после `npm run build` или правки
> `cordis.patch.yml` его нужно перезапустить.

> **Грабля.** `pnpm dsh` перед стартом гоняет `pnpm install` и может упасть на
> `postinstall` харнесса (`install-lefthook` в подмодуле git). Это отказ не харнесса,
> а проверки зависимостей: запуск из каталога, где `pnpm install` уже проходил, или
> `--config.verify-deps-before-run=false`.

## 4. Настройка ленты

**Настройки → Плагины → Конфигурация плагинов → «Управление коммуникацией»**:

| Поле | Что | Пример |
|---|---|---|
| Адрес ленты (фрейм) | клиент Phanpy | `http://127.0.0.1:8083` |
| Инстанс | сервер ленты, как его знает браузер | `https://feed.localtest.me` |
| Инстанс для узла | тот же сервер по http, если сертификат самоподписанный | `http://127.0.0.1:8080` |
| Токен человека | из `get_tokens.sh` | — |

«Проверить» ходит в инстанс с узла: `@aleks — токен принят`. Дальше — «Сохранить».

> **Грабля.** Адрес фрейма — только `127.0.0.1`, не `localhost`. Браузер делит хранилище
> фрейма по *сайту верхнего окна*: `127.0.0.1` с любым портом — один сайт, `localhost` —
> другой. С `localhost` фрейм не увидит вход, а внешне это «просит войти».

> **Грабля.** Инстанс во фрейме не открывается вовсе — `x-frame-options: DENY` на всём,
> включая страницу входа. Поэтому вход идёт не через OAuth, а посевом: узел отдаёт запись
> `localStorage.accounts` клиента, фрейм грузит `seed.html` клиента с ней во фрагменте
> адреса. Файл монтируется в контейнер клиента (`poh-feed-poc/compose.yml`). Без него
> nginx отдаст на `/seed.html` `index.html` клиента с кодом 200 — посев молча не сработает.

## 5. Метки

При первом запуске с пустым документом настроек узел **импортирует** существующий
`communication/labels.json` в настройки (а не зеркалит пустоту поверх него). Дальше
источник истины — документ настроек, а файл — зеркало, которое читают мост ленты,
перенос из Telegram и перемаркировка.

Правила «промт» требуют модели: `LABELS_LLM_BASE_URL`, `LABELS_LLM_API_KEY`,
`LABELS_LLM_MODEL` в `.env` ленты. Без них перемаркировка отказывается стартовать вслух.

## 6. Что должно получиться

1. Харнесс поднялся без ошибок про плагин.
2. Кнопка **«Управление коммуникацией»** в подвале левой панели.
3. Столбец справа с пилюлями и лентой — вход выполнен без страницы входа.
4. Карточка в «Настройки → Плагины».

Проверить одним прогоном: `npm run test:e2e` (против живого харнесса, см. `e2e/README.md`).
