# Подключение Telegram из интерфейса: спецификация

Статус: **спецификация, первый шаг** — код не написан, E2E-прогоны написаны против
этого текста и помечены ожидаемым падением (`e2e/03-telegram-setup.e2e.ts`). Записано
2026-09-14. Каждое ограничение ниже — из кода плагина и библиотеки, а не из предположений.

## AS IS

Telegram настраивается под капотом, и пользователю из интерфейса это недоступно:

| Что | Где сейчас | Кто делает |
|---|---|---|
| Ключ приложения `TG_API_ID`, `TG_API_HASH` | `.env` в корне пакета | руками в файле |
| Вход в аккаунт (код из приложения Telegram) | `node bin/login.mjs` в терминале | руками, один раз |
| Папки и чаты для сбора `WATCHED_FOLDERS`, `WATCHED_CHATS`, `WATCH_PRIVATE` | тот же `.env` | руками; список папок — `node bin/dialogs.mjs --folders` |
| Сбор | `node bin/collect.mjs`, отдельный процесс | руками |
| Проверка, что сбор идёт | отметка `collector.seenAt` в базе; наружу — только пустой Inbox | никто |

Из раздела в харнессе не видно ни того, подключён ли Telegram, ни почему нет.

## HowToDemo

1. Запускаю dsh.
2. Настройки → Плагины → Конфигурация плагинов.
3. Раскрываю карточку «Управление коммуникацией».
4. Над подключением ленты — полоса каналов; нажимаю иконку **Telegram**.
5. Раскрывается блок «Telegram»: ключ приложения и вход в аккаунт.
6. Рядом с заголовком блока — ссылка **«Смотреть инструкцию»**. Нажатие открывает справа
   боковую панель с заранее заготовленной инструкцией (Markdown со скриншотами): как
   получить App ID и API hash на my.telegram.org.
7. Ввожу App ID, API hash, номер телефона → **«Получить код»**. Telegram присылает код в
   приложение; ввожу код (и пароль двухфакторной защиты, если он включён) → **«Войти»**.
8. Блок подтверждает: «Вошли как <имя>», сессия сохранена.
9. После входа появляется выбор папок для отслеживания.
10. Раскрытие списка папок подгружает их из Telegram в этот момент, не из файла.
11. По умолчанию — **«Читать все»**. Отметка хотя бы одной папки снимает «Читать все»;
    возврат к «Читать все» снимает отметки с папок. Оба состояния одновременно невозможны.
12. **«Тест»** — в столбце справа открывается демо-режим: лента сообщений выбранных папок
    за последний час, прямо из Telegram.
13. Тест удался — иконка Telegram в полосе каналов переходит в состояние «подключено».
14. Тест не удался — в столбце вместо ленты текст: что сломалось и подсказка
    «введите команду `/dsh-communication fix-telegram`». Команда запускает режим отладки:
    агент прогоняет диагностику и говорит, что чинить.

## Ограничения, которые определяют конструкцию

**Ключа приложения мало для входа.** App ID и API hash — это ключ *приложения*, не
аккаунта. Вход в аккаунт — MTProto: номер телефона → код, который Telegram присылает в
уже залогиненное приложение, → при включённой двухфакторной защите ещё и пароль
(`sendCode` → `signIn` → `checkPassword` в mtcute). Шаг 7 обязан спросить телефон и код;
«и другие параметры» из постановки — это они. Альтернатива без ввода кода — вход по
QR-коду (`start({ qrCodeHandler })`): QR показывается в интерфейсе, сканируется телефоном.
В первой итерации — телефон и код; QR — следующая.

**Клиент Telegram не может жить в процессе харнесса.** Библиотека тянет нативный
модуль хранилища сессии, и несовместимый бинарь однажды уронил весь харнесс целиком
(`docs/ARCHITECTURE.md`, «Почему коллектор — отдельный процесс»). Поэтому всё, что
говорит с Telegram — вход, папки, тестовая лента, — выполняет **отдельный процесс-брокер**
`bin/tg-broker.mjs`, которого узел плагина поднимает на время операции и говорит с ним по
stdio строками JSON. Узел не импортирует `@mtcute/*` даже транзитивно.

**Секреты не в конфигурации репозитория.** Сейчас ключ и сессия — в `.env` пакета, и
это правильно. Настройки из интерфейса пишутся туда же: узел зеркалит поля пространства
настроек в `.env` (как `labels.json` для меток), а сессию заводит брокер файлом
`TG_SESSION`. Коллектор `bin/collect.mjs` не меняется: он читает то же, что раньше.

**Папки читаются в момент раскрытия.** Состав папки — у Telegram (`getFolders`), не у нас;
кэшировать значит показывать вчерашний список.

## Требования

| ID | Требование |
|---|---|
| БТ-1 | Product Owner подключает свой Telegram к разделу из интерфейса харнесса, без терминала и без правки файлов |
| БТ-2 | В любой момент видно, подключён ли Telegram, а если нет — почему и что делать |
| ПТ-1 | Полоса каналов в карточке раздела: иконка Telegram с состоянием `не настроен` / `нужен вход` / `подключено` / `ошибка` |
| ПТ-2 | Блок Telegram раскрывается по иконке; поля: App ID, API hash, телефон; кнопки «Получить код», «Войти»; поле кода и поле пароля 2FA появляются по ходу входа |
| ПТ-3 | «Смотреть инструкцию» открывает в столбце справа Markdown-инструкцию со скриншотами (`docs/guides/telegram-api-keys.md`) |
| ПТ-4 | После входа — список папок из Telegram, «Читать все» по умолчанию, взаимоисключающее с отметками папок |
| ПТ-5 | «Тест» показывает в столбце справа сообщения выбранных папок за последний час |
| ПТ-6 | Ошибка на любом шаге — текст ошибки в столбце и подсказка `/dsh-communication fix-telegram` |
| ИТ-1 | Узел говорит с Telegram только через процесс-брокер `bin/tg-broker.mjs` (stdio, JSON-строки) |
| ИТ-2 | Пространство настроек `communication-telegram`: `apiId`, `apiHash`, `phone`, `readAll`, `folders[]`; узел зеркалит их в `.env` пакета (`TG_API_ID`, `TG_API_HASH`, `WATCHED_FOLDERS`) |
| ИТ-3 | Сессия — файл `TG_SESSION`, заводится брокером при входе; узел проверяет её наличие для состояния иконки |
| ИТ-4 | Навык `dsh-communication` с аргументом `fix-telegram`: диагностика окружения, ключа, сессии, брокера, сбора |
| ФТ-1 | Вход: `sendCode(phone)` → `signIn(phone, hash, code)` → при `SessionPasswordNeeded` — `checkPassword`; результат — имя учётки |
| ФТ-2 | Папки: `getFolders()` брокера в момент раскрытия списка |
| ФТ-3 | Тестовая лента: сообщения выбранных папок (или всех диалогов при «Читать все») с `date >= now − 1h`, не более 50, от новых к старым |
| ФТ-4 | Тестовый режим брокера: `apiId = 1`, `apiHash = e2e-fake` — заглушка без сети (код `12345`, три папки, три сообщения за час); `apiHash = e2e-broken` — заглушка, у которой вход всегда падает с диагностируемой ошибкой |

## Контракты

### Пространство настроек `communication-telegram`

```yaml
apiId: 0            # число; 0 — не задан
apiHash: ''         # секрет: в снимке для браузера отдаётся только «задан/не задан»
phone: ''           # +7…, только для входа; сессия после входа телефон не требует
readAll: true
folders: []         # названия папок Telegram; непусто ⇒ readAll = false
```

Инвариант, который проверяет и клиент, и узел (`validate`): `readAll === true`
⇔ `folders.length === 0`.

### Подкоманды канала `/communication`

| Подкоманда | Вход | Выход |
|---|---|---|
| `telegram.status` | — | `{ state: 'unconfigured' \| 'needs-login' \| 'connected' \| 'error', detail, me? }` |
| `telegram.sendCode` | — (телефон из настроек) | `{ phoneCodeHash }` |
| `telegram.signIn` | `{ phoneCodeHash, code, password? }` | `{ me }` или `{ needsPassword: true }` |
| `telegram.folders` | — | `{ folders: [{ id, title }] }` |
| `telegram.test` | — | `{ messages: [{ chat, author, text, at }], collected: n }` |
| `telegram.doctor` | — | `{ checks: [{ name, ok, detail }] }` — то же, что делает навык |

Каждый отказ — `{ ok: false, error: { code, message } }` с текстом, годным показать
человеку; узел никогда не отвечает «внутренняя ошибка» на ожидаемые отказы Telegram
(неверный код, пароль, флуд-ожидание, `PHONE_NUMBER_INVALID`).

### Брокер `bin/tg-broker.mjs`

Одна строка JSON на запрос, одна на ответ; процесс живёт до `exit` или закрытия stdin.
Команды повторяют подкоманды выше. Ключ и путь сессии — из аргументов запуска, не из
`.env`: брокер обязан работать и с ещё не сохранёнными значениями формы.

### Столбец справа как поверхность для инструкции, теста и ошибок

Столбец «Лента контура» получает второй режим содержимого: вместо фрейма — панель
`Markdown` (инструкция) или список сообщений (тест) или текст ошибки с подсказкой. Режим
переключает карточка настроек через общий стор; закрытие столбца возвращает фрейм.

### Навык `/dsh-communication fix-telegram`

`skills/dsh-communication/SKILL.md` в пакете, подключается в профиль через
`customSkillDirs`. Аргумент `fix-telegram`: вызвать `telegram.doctor` (через
`node bin/doctor.mjs`), перечислить провалившиеся проверки и предложить починку по
таблице: нет ключа → инструкция; нет сессии → вход в карточке; брокер не стартует →
`npm install` / версия Node; сбор не идёт → `node bin/collect.mjs`.

## Что стоит знать

- Код из Telegram живёт минуты; форма держит `phoneCodeHash` только до «Войти».
- Флуд-ожидание (`FLOOD_WAIT_N`) — не ошибка конфигурации: показывать «повторите
  через N секунд», не подсказку про `fix-telegram`.
- «Читать все» в тесте берёт первые 20 диалогов по свежести — иначе тест по большому
  аккаунту идёт минуты.
- Сбор (`bin/collect.mjs`) после подключения из интерфейса по-прежнему запускается
  отдельно; его автозапуск — вне этой спецификации.

## Чего здесь нет

- Почты и MTS.Link: полоса каналов — с одной иконкой, место под другие заложено.
- QR-входа: следующая итерация, брокер уже даёт `start({ qrCodeHandler })`.
- Автозапуска коллектора вместе с харнессом.

## Приёмка

E2E `e2e/03-telegram-setup.e2e.ts` в тестовом режиме брокера (ФТ-4): шаги 2–14 один
к одному. Пока реализации нет, прогоны помечены `test.fail` с номером шага — они
считаются пройденными, если падают, и загорятся, когда шаг заработает: тогда пометку
снимают. Инструкция со скриншотами (`docs/guides/telegram-api-keys.md`) — отдельный
шаг после реализации.
